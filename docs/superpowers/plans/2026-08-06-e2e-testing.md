# E2E Testing (Maestro + Playwright on GitHub Actions) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every case in the phase-1b manual test plan that is not about the biometric app lock runs automatically on GitHub Actions, on both the Android app (Maestro) and the web app (Playwright).

**Architecture:** One local backend serves both suites — the Supabase CLI stack that `ci.yml`'s `db-tests` job already starts, plus `apps/api` (Nest) and, new here, a PowerSync Service container. Mobile runs a debug APK on an API 33 x86_64 emulator; the flows reach the signed-in app through a deep-link session route rather than Google OAuth. Maestro's `runScript` runs on the **host**, so it can mutate data server-side while the emulator's radios are off — that is what makes "edit it on the web" and the conflict run testable without a browser. Web reuses the same seeded user via a Playwright `storageState` built by `@supabase/ssr` itself.

**Tech Stack:** Maestro CLI, Playwright, `reactivecircus/android-emulator-runner`, Supabase CLI (already a pinned devDependency), `journeyapps/powersync-service` Docker image, Node 22, pnpm 11, Turborepo.

## Global Constraints

- **Public repo.** `thanhphuong080199/cortex` is `"visibility":"PUBLIC"`, so GitHub Actions standard runners are free and unmetered. Minute counts in this plan are about PR latency, not quota.
- **Never `pnpm --filter <pkg> test`.** Always `pnpm turbo run test --filter=<pkg>`; `@cortex/shared` and `@cortex/core` are consumed as compiled `dist/`. Same rule as `ci.yml`.
- **New suites must be named in a workflow step** or they run nowhere but a developer's machine. Both new workflows are the mechanism for the suites this plan adds.
- **`EXPO_PUBLIC_E2E=1` may only ever be set in `.github/workflows/e2e-mobile.yml`.** Not in `eas.json`, not in `app.json`, not in `android-apk.yml`. Task 3 adds a build-time guard that enforces this.
- **`apps/mobile/android/` is gitignored** and regenerated by `expo prebuild` on every run. Anything that must change in it is a patch step in the workflow, never a tracked edit.
- **No `.env` file may reach a runner.** `ci.yml` already fails the build if one does (every vitest config sets `setupFiles: ["dotenv/config"]`, which would silently backfill missing env vars). Keep that property.
- **Node 22, pnpm via `pnpm/action-setup@v4`, `actions/setup-node@v4` with `cache: pnpm`** — match the existing workflows exactly.

Task 6's `wait-for-download` catches the bug if it is in the code; it cannot catch it if it is in the environment. Closing that issue still needs one manual run on hardware.

### Task 1: PowerSync Service running against the local Supabase stack

- Create: `e2e/powersync/up.sh`
- Delete: `e2e/powersync/docker-compose.yml` (the Mongo-based draft)

**Interfaces:**
- Produces: a PowerSync Service reachable at `http://127.0.0.1:8080` from the host and `http://10.0.2.2:8080` from the emulator, serving the streams in `packages/sync/src/sync-rules.yaml`.
- Consumes: `SUPABASE_URL`, and Supabase local Postgres at `postgresql://postgres:postgres@127.0.0.1:54322/postgres`.

- [ ] **Step 1: Confirm the local stack can do logical replication at all**

PowerSync replicates by logical decoding. If `wal_level` is not `logical`, nothing downstream works and the failure surfaces as a silent empty bucket.

```bash
pnpm exec supabase start -x realtime,storage-api,studio,edge-runtime,logflare,vector,postgres-meta,mailpit
psql "postgresql://postgres:postgres@127.0.0.1:54322/postgres" -c "show wal_level;"
psql "postgresql://postgres:postgres@127.0.0.1:54322/postgres" -c "select pubname from pg_publication;"
```

Expected: `wal_level = logical`, and a publication named `powersync` (created by `supabase/migrations/00016_powersync_publication.sql`).

If `wal_level` is not `logical`, stop and add `[db.settings] wal_level = "logical"` to `supabase/config.toml` before continuing — every later task depends on this.

- [ ] **Step 2: Write the config**

Bucket storage goes in a **separate database** on the same server, so PowerSync's own tables never appear in the replicated schema.

```yaml
# e2e/powersync/config.yaml
replication:
  connections:
    - type: postgresql
      uri: !env PS_REPLICATION_URI
      sslmode: disable

storage:
  type: postgresql
  uri: !env PS_STORAGE_URI
  sslmode: disable

client_auth:
  supabase: true
  jwks_uri: !env PS_JWKS_URI
  audience: ["authenticated"]

sync_rules:
  path: /config/sync-rules.yaml
```

- [ ] **Step 3: Write the startup script**

```bash
#!/usr/bin/env bash
# e2e/powersync/up.sh — start PowerSync Service against the local Supabase stack.
set -euo pipefail

PG="postgresql://postgres:postgres@127.0.0.1:54322"
export PS_REPLICATION_URI="${PG}/postgres"
export PS_STORAGE_URI="${PG}/powersync_storage"
export PS_JWKS_URI="${SUPABASE_URL:?}/auth/v1/.well-known/jwks.json"

# Bucket storage needs its own database; creating it here keeps it out of the migrations,
# which describe the product's schema and must not gain a test-only database.
psql "${PG}/postgres" -c "SELECT 1 FROM pg_database WHERE datname='powersync_storage'" \
  | grep -q 1 || psql "${PG}/postgres" -c "CREATE DATABASE powersync_storage"

# The config is passed base64-encoded rather than mounted: that is the documented mechanism,
# and it means !env substitution happens inside the container with the vars set below.
docker run -d --name cortex-powersync --network host \
  -e POWERSYNC_CONFIG_B64="$(base64 -w0 "$(dirname "$0")/config.yaml")" \
  -e PS_REPLICATION_URI -e PS_STORAGE_URI -e PS_JWKS_URI \
  -v "$(cd "$(dirname "$0")/../../packages/sync/src" && pwd)/sync-rules.yaml:/config/sync-rules.yaml:ro" \
  journeyapps/powersync-service:latest

# --network host means the container's port 80 IS the host's port 80, which collides with
# anything else there. Verify the actual listening port before relying on 8080.
for i in $(seq 1 60); do
  curl -fsS http://127.0.0.1:8080/probes/liveness && exit 0
  sleep 2
done
echo "powersync did not become live" >&2
docker logs cortex-powersync >&2
exit 1
```

### Task 4: A debug APK that runs without Metro

**Files:**
- Create: `e2e/scripts/patch-android.mjs`
- Create: `e2e/scripts/assert-manifest.sh`

**Interfaces:**
- Produces: `apps/mobile/android/app/build/outputs/apk/debug/app-debug.apk`, self-contained.
- Consumes: `apps/mobile/android/` as generated by `expo prebuild`.

**Why this task exists:** a plain `assembleDebug` APK does not embed the JS bundle — it expects a Metro dev server, which in CI means a background process plus `adb reverse` and a whole class of flake. `android/` is gitignored and regenerated, so the fix is a patch step, not a tracked edit.

- [ ] **Step 1: Write the patch script**

```javascript
#!/usr/bin/env node
// e2e/scripts/patch-android.mjs — post-prebuild edits for the E2E debug APK ONLY.
//
// apps/mobile/android/ is gitignored and regenerated by `expo prebuild` on every run, so these
// cannot be tracked edits. They are also things that must NOT be true of a release build, which
// is a second reason they live here rather than in app.json.
import { readFileSync, writeFileSync } from "node:fs";

const gradle = "apps/mobile/android/app/build.gradle";
let g = readFileSync(gradle, "utf8");

// Without this the debug APK contains no JS and boots to a red screen asking for Metro.
if (!/bundleInDebug/.test(g)) {
  g = g.replace(/react\s*\{/, "react {\n    bundleInDebug = true");
  writeFileSync(gradle, g);
  console.log("patched: bundleInDebug = true");
} else {
  console.log("bundleInDebug already present");
}

const manifest = "apps/mobile/android/app/src/main/AndroidManifest.xml";
let m = readFileSync(manifest, "utf8");

// The emulator reaches Supabase, the API and PowerSync over plaintext http on 10.0.2.2.
// Android 9+ blocks cleartext by default, and the symptom is an opaque network failure inside
// the sync stream rather than anything that names TLS.
if (!/usesCleartextTraffic/.test(m)) {
  m = m.replace(/<application /, '<application android:usesCleartextTraffic="true" ');
  writeFileSync(manifest, m);
  console.log("patched: usesCleartextTraffic=true");
}

// allowBackup=false comes from app.json and is a §7.6 security property, not a preference.
// Asserting it here means the E2E build fails loudly if app.json ever loses it -- which is
// mục 2's `adb backup` row, checked at the property rather than through a dialog that modern
// Android will not show unattended anyway.
if (!/android:allowBackup="false"/.test(m)) {
  console.error("::error::AndroidManifest is missing android:allowBackup=\"false\"");
  process.exit(1);
}
console.log("verified: allowBackup=false");
```


Expected: a `react { ... }` block. Confirm it accepts `bundleInDebug`; if the generated block already sets `enableBundleCompression` or similar, match the surrounding style. If `bundleInDebug` is not supported by this RN version's Gradle plugin, the fallback is `assembleRelease` (which `android-apk.yml` already proves works and embeds JS via `expo export:embed`) — record whichever was used.

```javascript
// Post-reconnect assertions that the device cannot make about itself: exact row counts, the
// shape of the conflict copy, and whether created_at kept the capture time.
var REST = SUPABASE_URL + "/rest/v1";

function get(path) {
  var res = http.get(REST + path, {
    headers: {
      apikey: SUPABASE_ANON_KEY,
      Authorization: "Bearer " + ACCESS_TOKEN,
      Accept: "application/json",
    },
  });
  if (!res.ok) throw new Error("GET " + path + " -> " + res.status + " " + res.body);
  return json(res.body);
}

// Polls, because the upload queue drains asynchronously after the radios return. Each request
// costs real time, which paces the loop -- Maestro's JS runtime has no setTimeout.
function eventually(fn, label) {
  for (var i = 0; i < 60; i++) {
    var v = fn();
    if (v !== null) return v;
  }
  throw new Error("timed out waiting for: " + label);
}

// --- 1. the offline capture arrived, exactly once ---
eventually(function () {
  var r = get("/notes?select=id,created_at&content=eq." + encodeURIComponent(CAPTURE_MARKER));
  return r.length === 1 ? r : null;
}, "the offline capture to upload exactly once");

// --- 5a. the double-tapped Save produced ONE note, not two ---
var dbl = get("/notes?select=id&content=eq." + encodeURIComponent(DOUBLE_TAP_MARKER));
if (dbl.length !== 1) {
  throw new Error("double-tapped Save produced " + dbl.length + " notes, expected 1");
}

// --- 7. the conflict copy ---
var server = get(
  "/notes?select=id,content,lifecycle&id=eq." + NOTE_CONFLICT_TARGET
);
if (server.length !== 1) throw new Error("the original conflict note vanished");
if (server[0].content.indexOf("SERVERBODY") !== 0) {
  throw new Error(
    "the original note should keep the WEB body, it has: " + server[0].content
  );
}

var copies = get(
  "/notes?select=id,content,lifecycle&content=like.DEVICEBODY*&deleted_at=is.null"
);
if (copies.length !== 1) {
  throw new Error("expected exactly 1 conflict copy, found " + copies.length);
}
if (copies[0].id === NOTE_CONFLICT_TARGET) {
  throw new Error("the device body overwrote the original instead of making a copy");
}
if (copies[0].lifecycle !== "inbox") {
  throw new Error("the conflict copy must land in inbox, got " + copies[0].lifecycle);
}

// --- 2. the offline trash stuck ---
var trashed = get("/notes?select=id,deleted_at&id=eq." + NOTE_TRASH_TARGET);
if (trashed.length !== 1 || trashed[0].deleted_at === null) {
  throw new Error("the note trashed offline came back un-trashed after the reconnect");
}

// --- 8. the undone check-in left nothing ---
var checkins = get("/checkins?select=id&mood=eq.2&deleted_at=is.null");
if (checkins.length !== 0) {
  throw new Error("undo left " + checkins.length + " check-in(s) on the server");
}

// --- mục 5. created_at is the CAPTURE time, not the reconnect time ---
// The note was captured minutes before the radios returned; if created_at were stamped on
// upload it would be within seconds of now.
var captured = get(
  "/notes?select=created_at&content=eq." + encodeURIComponent(CAPTURE_MARKER)
);
var ageMs = Date.now() - Date.parse(captured[0].created_at);
if (ageMs < 20000) {
  throw new Error(
    "created_at looks like the reconnect time (" + ageMs + "ms ago), not the capture time"
  );
}
```

```typescript
// apps/web/e2e/global-setup.ts
import { createServerClient } from "@supabase/ssr";
import { mkdirSync, writeFileSync } from "node:fs";
import { dirname } from "node:path";

const AUTH_FILE = "e2e/.auth/user.json";

export default async function globalSetup() {
  const jar: { name: string; value: string; options: Record<string, unknown> }[] = [];

  // The SAME client the app uses server-side. Letting it write into a throwaway jar is what
  // makes the cookie names, chunking and encoding correct by construction -- hand-rolling
  // `sb-<ref>-auth-token` would be a second implementation to keep in sync with the library.
  const supabase = createServerClient(
    process.env.NEXT_PUBLIC_SUPABASE_URL!,
    process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY!,
    {
      cookies: {
        getAll: () => jar.map(({ name, value }) => ({ name, value })),
        setAll: (toSet) => { jar.length = 0; jar.push(...toSet); },
      },
    },
  );

  const { error } = await supabase.auth.signInWithPassword({
    email: process.env.E2E_EMAIL ?? "e2e@cortex.test",
    password: process.env.E2E_PASSWORD ?? "e2e-password-not-a-secret",
  });
  if (error) throw new Error(`E2E sign-in failed: ${error.message}`);
  if (jar.length === 0) throw new Error("sign-in wrote no cookies; nothing to persist");

  const url = new URL(process.env.E2E_WEB_URL ?? "http://127.0.0.1:3000");
  mkdirSync(dirname(AUTH_FILE), { recursive: true });
  writeFileSync(
    AUTH_FILE,
    JSON.stringify({
      cookies: jar.map((c) => ({
        name: c.name,
        value: c.value,
```

- [ ] **Step 1: Write it**

```yaml
name: E2E Web

# Every PR to main, as specified: the whole job is under ten minutes, so there is no reason to
# path-filter it the way the mobile one is.
on:
  pull_request:
    branches: [main]

concurrency:
  group: e2e-web-${{ github.ref }}
  cancel-in-progress: true

jobs:
  e2e:
    runs-on: ubuntu-latest
    timeout-minutes: 25
    env:
      SUPABASE_URL: http://127.0.0.1:54321
      E2E_API_URL: http://127.0.0.1:3001
      E2E_WEB_URL: http://127.0.0.1:3000

    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: pnpm

      - run: pnpm install --frozen-lockfile

      - name: Assert no .env files reached the runner
        run: |
          found=$(find . -name .env -not -path '*/node_modules/*')
          if [ -n "$found" ]; then echo "::error::$found"; exit 1; fi

      - name: Start Supabase
        run: >
          pnpm exec supabase start
          -x realtime,storage-api,studio,edge-runtime,logflare,vector,postgres-meta,mailpit

      - name: Export Supabase keys
        run: |
          eval "$(pnpm exec supabase status -o env | grep -E '^(ANON_KEY|SERVICE_ROLE_KEY)=')"
          {
            echo "SUPABASE_ANON_KEY=$ANON_KEY"
            echo "SUPABASE_SERVICE_ROLE_KEY=$SERVICE_ROLE_KEY"
            echo "NEXT_PUBLIC_SUPABASE_URL=http://127.0.0.1:54321"
            echo "NEXT_PUBLIC_SUPABASE_ANON_KEY=$ANON_KEY"
            echo "NEXT_PUBLIC_API_URL=http://127.0.0.1:3001"
          } >> "$GITHUB_ENV"

      - name: Build
        run: pnpm turbo run build --filter=@cortex/web --filter=@cortex/api

      - name: Start the API
        run: |
          node apps/api/dist/main.js &
          for i in $(seq 1 30); do curl -fsS http://127.0.0.1:3001/health && break; sleep 2; done
        env:
          PORT: 3001
          CORS_ORIGINS: http://127.0.0.1:3000,http://localhost:3000

      # Keyed on the Playwright version, because the browser build is pinned to it. A plain
      # lockfile hash would miss the case where only Playwright moves.
      - name: Cache Playwright browsers
        uses: actions/cache@v4
        id: pw-cache
        with:
          path: ~/.cache/ms-playwright
          key: playwright-${{ hashFiles('pnpm-lock.yaml') }}

      - name: Install Chromium
        run: pnpm --filter @cortex/web exec playwright install --with-deps chromium

      - name: Seed
        run: |
          node e2e/scripts/seed.mjs --reset > /tmp/seed.json
          echo "E2E_ACCESS_TOKEN=$(jq -r .accessToken /tmp/seed.json)" >> "$GITHUB_ENV"

      - name: Run Playwright
        run: pnpm --filter @cortex/web exec playwright test

      - uses: actions/upload-artifact@v4
        if: failure()
        with:
          name: playwright-report
          path: |
            apps/web/playwright-report/
            apps/web/test-results/
          if-no-files-found: warn
          retention-days: 14
```

Note `--with-deps` runs even on a cache hit: the cache restores browser binaries but not the apt libraries they link against.
